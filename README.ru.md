# ztos-ugglite — адаптация для Xiaomi Redmi Note 5A (ugglite)

*English version: [README.md](README.md)*

Слой устройства, рецепт сборки и небольшой явно описанный набор патчей для
запуска [ztOS](https://github.com/Zerone-Laboratories/ztOS) на Xiaomi Redmi
Note 5A (`ugglite`, Qualcomm MSM8917, Adreno 308) с mainline-ядром
`linux-postmarketos-qcom-msm89x7` и lk2nd в качестве первой ступени загрузки.

Неофициально и экспериментально. Это не продукт, не установщик и не
поддерживаемое устройство ztOS или postmarketOS. Проверенное состояние — вручную
собранный корень, загружаемый с хоста по USB; часть ключевых функций не
проверена или не работает.

## Состояние железа

| Область | Состояние |
|---|---|
| Загрузка ядра и userspace по USB (lk2nd → RAM-кандидат) | работает |
| Экран, базовая сборка | работает — подтверждено владельцем устройства |
| Яркость экрана | Работает на принятой RAM-сборке с сохранением DSI video clocks. Владелец подтвердил плавную регулировку без сдвига кадра |
| Wi-Fi | ассоциация и трафик работают; скорость/rate под нагрузкой не исправлены |
| Звук | штатный путь играет с шипением в простое; заменяющий путь отклонён на железе |
| Запись RTC | **небезопасно, не делать**; причина не установлена |
| Модем | LTE-регистрация, уровень сигнала и индикатор в UI работают; **data/APN, SMS, звонки, call audio и GNSS не проверены** — [docs/modem.md](docs/modem.md) |
| Время без сети | системные часы верны без NTP через `swclock-offset`; запись hardware RTC по-прежнему небезопасна |
| Задняя камера | Определяется S5K3L8, получен RAW10 1280×720. Экспозиция сцены и preview приложения не приняты |
| Suspend | не проверен |

Подробности и границы доказательств: [docs/hardware-status.md](docs/hardware-status.md).
Перед работой с устройством: [docs/safety.md](docs/safety.md).

## Что здесь есть

```
devices/xiaomi-ugglite/
  device.toml                 запись реестра: пин pmaports, ядро, DTB, lk2nd
  layer.sh                    apply <root>: копирует overlay/ в готовый корень
  fixups.sh                   идемпотентные правки после копирования (setuid, pacman)
  packages.txt                дополнительные пакеты для собранного корня
  overlay/                    файлы, накладываемые на корень
  patches/                    серия патчей, порядок — в SERIES.md
build-environment/
  Dockerfile                  образ сборки: нативный aarch64 Arch Linux ARM
  prepare-kernel.sh           сборка ядра в отдельном контейнере, пин pmaports
  finalize-kernel.sh          сборка/проверка/экспорт внутри контейнера, отказ при дрейфе
  repack-boot-init.py         замена только init внутри готового boot-образа
docs/                         состояние железа, безопасность
SERIES.md                     порядок патчей, базовые коммиты, цепочка хешей
PROVENANCE.md                 лицензии и происхождение каждого файла
MAP.md                        каждый рабочий компонент → путь или причина исключения
LICENSES/, NOTICE.md          тексты лицензий и границы по областям
```

Серия включает шесть патчей userspace и две дельты ядра. Порядок,
исходные версии и границы приёмки приведены в [SERIES.md](SERIES.md).

## Как воспроизвести сборку

Из чистого checkout можно подготовить закреплённые исходники userspace,
собрать пакет ядра в ARM64-контейнере и наложить слой устройства на готовый
rootfs. Команды и недостающие входы для загрузочного образа перечислены
в [документации сборки](docs/BUILD-AND-BOOT.md).
На x86_64 потребуется настроенная эмуляция aarch64 через binfmt.

Версии upstream закреплены URL и коммитом в `ATTRIBUTION.md`; это версии,
против которых сделаны патчи, а не обещание, что они всё ещё собираются.

## Границы публикации

- Никаких бинарников, образов, пакетов ядра, firmware и собранных логов.
- Никаких учётных данных, сетевых профилей, имён хостов, идентификаторов
  устройства и личных путей.
- Патча записи RTC нет: это небезопасно на этом железе.
- Отклонённые и непринятые эксперименты не публикуются как функции; если
  дельта имеет ценность, но не принята, она лежит в `experimental/` с явно
  указанным ограничением.
