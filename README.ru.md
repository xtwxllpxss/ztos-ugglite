# ztos-ugglite — адаптация устройства для Xiaomi Redmi Note 5A (ugglite)

*English version: [README.md](README.md)*

Оверлей устройства, заметки о сборке и небольшой набор принятых патчей для
запуска [ztOS](https://github.com/Zerone-Laboratories/ztOS) на Xiaomi Redmi
Note 5A (`ugglite`, Qualcomm MSM8917, Adreno 308) с mainline-ядром
`linux-postmarketos-qcom-msm89x7` и lk2nd в роли загрузчика.

**Это неофициальная экспериментальная адаптация с загрузкой RAM-образа с
хоста. Это не продукт, не установщик и не официально поддерживаемое устройство
ztOS.** Проекты ztOS и postmarketOS её не одобряли. Установки одной командой
нет: проверенное состояние — вручную собранный корень, загруженный по USB с
хоста, и часть ключевых функций не проверена или не работает — последний
дисплейный кандидат в их числе (см.
[статус](docs/hardware-status.md)).

## Что работает, а что нет

Кратко, по последней аппаратной сессии:

| Область | Состояние |
|---|---|
| Ядро / RAM-загрузка до userspace | работает (baseline ztOS `4fed0f28…` загружен через lk2nd) |
| Дисплей | после отката владелец устройства подтвердил работу экрана на baseline; замена панельного модуля дала чёрный экран и отклонена; управление яркостью из UI пока не исправлено (`EACCES`) |
| Звук | штатный путь играет с шипением на idle; замена (C2) отклонена на железе |
| Wi-Fi | работает с ограничениями (поведение скорости не исправлено) |
| Запись RTC | **небезопасна, не выполнять** — причина падения не установлена |
| Модем, камера, suspend | **не проверены** — утверждений нет |

Подробности, границы доказательств и открытые отказы: [docs/hardware-status.md](docs/hardware-status.md).

## Структура репозитория

```
devices/xiaomi-ugglite/
  device.toml                 запись реестра (пины pmaports, ядро, lk2nd, SoC)
  layer.sh                    apply <root>: копирует overlay/ в готовый корень
  fixups.sh                   идемпотентные правки после копирования (setuid, sandbox pacman)
  packages.txt                дополнительные пакеты для собранного корня
  overlay/                    файлы, копируемые поверх корня
  patches/                    патчи устройства, принятые в ходе bring-up
docs/                         статус железа и заметки по безопасности
LICENSES/                     полные тексты лицензий; область действия — в NOTICE.md
```

В `device.toml` намеренно не задан `[boot].rootfs_target`: выбор носителя —
решение того, кто собирает образ, и драйвер сборки требует его явно. Поэтому
запись **не самодостаточна**: это входные данные, а не готовый пакет устройства.

## Сборка и загрузка — что воспроизводимо

Здесь воспроизводимы только *входные данные*, а не образ. Нужен хост с
pacstrap/arch-chroot (или pmbootstrap), `mkbootimg`, `mke2fs` и aarch64
кросс-окружением; в репозитории нет бинарников, ядра, firmware и образов.
Проверенный путь был таким:

1. Собрать корень Arch Linux ARM с запиненным пакетом ядра
   (`linux-postmarketos-qcom-msm89x7` 7.1.3-r1) и DTB ugglite
   `qcom/msm8917-xiaomi-ugglite.dtb`.
2. Применить слой: `layer.sh apply <root>`, затем `fixups.sh <root>`.
3. Загрузить этот корень как RAM-кандидат через lk2nd, имея USB единственной
   консолью — и никогда не прошивая раздел.

Собранный корень жил на хосте и в `userdata`, поэтому **автоматический
установщик, образ для отката и процедура восстановления здесь не
публикуются.** Если у вас уже нет рабочей загрузки с хоста, этот репозиторий её
не даст.

Запиненные ревизии upstream и их происхождение — в
[ATTRIBUTION.md](ATTRIBUTION.md); это ревизии, под которые писались заметки, а
не гарантия, что сборка пройдёт сегодня.

## Статус и рамки публикации

- Не официальный артефакт ztOS или postmarketOS; одобрения upstream нет.
- Гарантий поддержки нет. Issues читаются, но сломанное устройство — ваш риск.
- Намеренно исключены: бинарники, образы, firmware, приватная конфигурация,
  сетевые профили, учётные данные, сырые аппаратные логи и непроверенные
  экспериментальные патчи. Причины и allowlist — в [NOTICE.md](NOTICE.md).
