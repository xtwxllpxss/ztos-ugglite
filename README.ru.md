# ztos-ugglite — адаптация для Xiaomi Redmi Note 5A (ugglite)

*English version: [README.md](README.md)*

Слой устройства, рецепт сборки и небольшой явно описанный набор патчей для
запуска [ztOS](https://github.com/Zerone-Laboratories/ztOS) на Xiaomi Redmi
Note 5A (`ugglite`, Qualcomm MSM8917, Adreno 308) с mainline-ядром
`linux-postmarketos-qcom-msm89x7` и lk2nd в качестве первой ступени загрузки.

Неофициально и экспериментально. Это не продукт, не установщик и не
поддерживаемое устройство ztOS или postmarketOS. Проверенное состояние — постоянная
установка: в boot-слоте лежат lk2nd и payload ztOS (stock boot сохранён для
отката), ztOS работает с внутреннего ext4-корня; часть ключевых функций всё ещё
не проверена или не работает.

## Состояние железа

«Принято» означает, что функцию подтвердил владелец устройства на телефоне.
Если число получено host-сборкой или из сохранённого лога, это сказано в строке.

| Область | Состояние |
|---|---|
| Загрузка, постоянная (lk2nd + boot-слот ztOS) | работает — перезагрузки без хоста; stock boot сохранён для отката |
| Загрузка, RAM-кандидаты (`fastboot boot`) | работают — проверка ядра/DT без записи слота |
| Время загрузки / splash | **установлено и принято** — compositor splash-fast убирает splash за **6.306 с** вместо 51.047 с по собственным часам композитора. 51 с — это boot-гейт, ждавший маркер Waydroid, который эта установка никогда не писала; установленная сборка ждёт только если интеграция установлена (замер на одной загрузке той же установки; общее «кнопка → UI» по-прежнему не измерено) — [docs/boot-time.md](docs/boot-time.md) |
| Экран, базовая сборка | работает — подтверждено владельцем устройства |
| Яркость экрана | Работает в принятой постоянной установке с сохранением DSI video clocks. Владелец подтвердил плавную регулировку без сдвига кадра |
| Wi-Fi | ассоциация и трафик работают; скорость/rate под нагрузкой не исправлены |
| Звук | динамик и звук входящего звонка приняты (RX1/RX2 104 в принятом тесте усиления; установленный verb пишет 120, +36 dB, громче без дисторшна); шипение в простое остаётся. Микрофон тихий, кандидаты усиления не приняты |
| Запись RTC | **небезопасно, не делать**; причина не установлена |
| Модем | LTE-регистрация и индикатор в UI работают; **входящие звонки и звук звонка приняты**, приём SMS импортирует сообщения, data on/off и autoconnect приняты; исходящие звонки не проверены, отправка SMS падает (RP cause 38), WWAN-данные не подтверждены (allow-list тарифа). Как реально идёт приём (QMI WMS) и кандидат дедупа: [docs/sms.md](docs/sms.md) — [docs/modem.md](docs/modem.md) |
| GNSS | GPS-движок модема проверен (NMEA, спутник с SNR 31); пользовательского клиента нет. Подготовленный GeoClue-клиент описан, но не установлен — [docs/gnss.md](docs/gnss.md) |
| Время без сети | системные часы верны без NTP через `swclock-offset`; запись hardware RTC по-прежнему небезопасна |
| Задняя камера | S5K3L8 определён, захват RAW10 1280×720 проверен; владелец подтверждает работу камеры. Сенсорный путь измерен на 119.44 fps, кандидатный бинарь ограничивает его до 29.84 fps с выдержкой до 1/30 c, но этот бинарь не установлен. Ограничение vblank, AF settle/boost и ретайм пейсера опубликованы как **кандидатные патчи исходника** (host-проверены, на телефоне не запускались). Запись 720p30, калибровка цвета, AE/ISO и ощущение AF не приняты — [docs/camera-video.md](docs/camera-video.md), [SERIES.md](SERIES.md) |
| Фронтальная камера | S5K5E8 chip ID `0x5e80`, оба CSI-линка и захват 640×480 проверены; владелец подтверждает работу камеры. Причина `Loading…` в приложении камеры найдена, фикс доставлен и принят: живое превью с `/dev/video1` 640×480, около **62 fps** (бинарь после фикса `c2a28339…`, предыдущий `ea79a1c8…` сохранён в backup). Ориентация/зеркало превью, высокие режимы и AE не приняты — [docs/front-camera.md](docs/front-camera.md) |
| Задний фонарик | работает — DT-only узел `gpio-leds` `white:torch` на gpio34, доступ для UI через udev-правило; `max_brightness=1`, только on/off. Маппинг GPIO взят из вендорского DT/драйвера |
| Сенсоры / авто-поворот | **сенсорный хаб исправлен, установлен и проверен после одной перезагрузки** — реестр сенсоров грузится за 3.215 с, ADSP поднимается за 3.886 с, именно в этом порядке (до фикса успех был только ~7.6 с через late fallback); `/dev/iio:device1..4` при остановленном потребителе дают 24/24/24/16 байт на скан, `zt-sensors` живой (акселерометр, гироскоп, магнитометр, приближение, значения меняются). Авто-поворот разблокирован на уровне сенсоров (`rotate --set on` принимается без ошибок, конфиг восстановлен байт-в-байт), но поворот в композиторе **не реализован** (плитка ROTATION LOCK — заглушка), физический наклон не выполнялся — визуальный поворот не принят — [docs/sensors.md](docs/sensors.md), [docs/auto-rotate.md](docs/auto-rotate.md) |
| Приложения / UI | Обследованы 35 приложений, все 35 закрыты: **PASS 12 · PARTIAL 11 · FAIL 10 · HIDDEN 1** (плюс один невалидный кадр — Firefox, измерен отдельно). После приёмки доставлены фиксы: runtime vim, глифы/центрирование калькулятора, конфиг btop, телеметрия Power Management (upstream PR #16) и превью фронтальной камеры. Store и OSIAL **работают** — Store рисует списки пакетов AUR/репозиториев, OSIAL выдаёт 13 интерфейсов за 1.9 с; единственный видимый сбой — `pkgstats.archlinux.org` не резолвится (DNS), это видно на экране. Поворот в композиторе не реализован (плитка ROTATION LOCK — заглушка); `ztgallery` v2 (папки/альбомы, видео, скролл) в разработке. Открыто: обрезка UI на 360×640@2, тумблеры, статус камеры `0 fps` — [docs/apps.md](docs/apps.md), [docs/store-and-osial.md](docs/store-and-osial.md) |
| Waydroid | **freeze-политика установлена и проверена** — helper переживает screen-off/on (`verify.sh` 12/0), сессия стартует примерно за 5 с, Android 13 доходит до `boot_completed=1`, запущенное вручную приложение рисует реальное окно, screen-off-политика ztmetro завершается. Это не полная интеграция: нет `recover`/`launch`-юнитов, ANR `systemui` на 2 ГБ, ручной старт при выключенном экране остаётся замороженным до thaw; запуск Android из плитки ztmetro не реализован и визуально не подтверждён — владелец отложил эту работу на самый конец; образы и userdata не тронуты — [docs/waydroid.md](docs/waydroid.md) |
| Принятие upstream | PR #16 влит на принятую базу и установлен на телефон: `ztpower`, `ztdevices`, `ztsettings` заменены сборками из upstream-исходника, проверено вживую — ненулевая телеметрия батареи (`100 %`, `Charging (+30 mA)`, `4.38 V`, `31.4 °C`; sysfs 4.382 V сходится), окна settings и devices рисуются, segfault нет, прежние бинари сохранены в backup. PR #13 принят кроме камерных хунков, пока не влит; #14 отброшен как дубль, #11 не нужен — [docs/upstream.md](docs/upstream.md) |
| Обновления | `ztos-update check` завершается; `apply` обновляет одним `pacman -Syu` |
| Память / браузер | zram (900 MB, `lz4`) активен; изменения памяти и Firefox-pref — host-only рекомендации, **ничего не применено**. Есть один живой замер браузера: WebRender через EGL/freedreno активен (DPR 2), 10 процессов, PSS ~630 MB, OOM нет; медиана 32.9 мс во фрейм-трейсе — это **цикл композитора** (mean 28.08 мс ≈ 35.6 fps), **не** fps Firefox; гипотеза present/dmabuf открыта, план A/B есть и не применён — [docs/performance.md](docs/performance.md) |
| Venus, аппаратное кодирование видео | probe проходит в текущей загрузке, синтетический H.264 720p кодируется, но прошивка локальна для устройства и не публикуется, поведение после reboot не проверено, камера её пока не использует. | Suspend | `deep` не поддерживается прошивкой; только `s2idle`, расход в screen-off не измерен |

## Что здесь есть

```
devices/xiaomi-ugglite/
  device.toml                 запись реестра: пин pmaports, ядро, DTB, lk2nd
  layer.sh                    apply <root>: копирует overlay/ в готовый корень
  fixups.sh                   идемпотентные правки после копирования (setuid, pacman)
  packages.txt                дополнительные пакеты для собранного корня
  overlay/                    файлы, накладываемые на корень
  patches/                    серия патчей, порядок — в SERIES.md
build-environment/
  Dockerfile                  образ сборки: нативный aarch64 Arch Linux ARM
  prepare-kernel.sh           сборка ядра в отдельном контейнере, пин pmaports
  finalize-kernel.sh          сборка/проверка/экспорт внутри контейнера, отказ при дрейфе
  repack-boot-init.py         замена только init внутри готового boot-образа
docs/                         состояние железа, камера и видео (две линии исходника), фронтальная камера, Venus, Store и OSIAL, приём SMS, авто-поворот, сенсоры, приёмка приложений, принятие upstream, восстановление, GNSS-клиент, Waydroid, время загрузки, производительность, термалка, безопасность
SERIES.md                     порядок патчей, базовые коммиты, цепочка хешей
PROVENANCE.md                 лицензии и происхождение каждого файла
MAP.md                        каждый рабочий компонент → путь или причина исключения
LICENSES/, NOTICE.md          тексты лицензий и границы по областям
```

Серия включает шесть патчей userspace `ztmetro`, составную дельту приложения
камеры и три кандидатные дельты камеры (host-проверены, на телефоне не
запускались), кандидатную дельту SMS-приёма в слое устройства и три дельты ядра
(0003 — кандидат, не принятое состояние).
Порядок, исходные версии и границы приёмки приведены в [SERIES.md](SERIES.md).

## Как воспроизвести сборку

Из чистого checkout можно подготовить закреплённые исходники userspace,
собрать пакет ядра в ARM64-контейнере и наложить слой устройства на готовый
rootfs. Команды и недостающие входы для загрузочного образа перечислены
в [документации сборки](docs/BUILD-AND-BOOT.md).
На x86_64 потребуется настроенная эмуляция aarch64 через binfmt.

Версии upstream закреплены URL и коммитом в `ATTRIBUTION.md`; это версии,
против которых сделаны патчи, а не обещание, что они всё ещё собираются.

## Границы публикации

- Никаких бинарников, образов, пакетов ядра, firmware и собранных логов.
- Никаких учётных данных, сетевых профилей, имён хостов, идентификаторов
  устройства и личных путей.
- Патча записи RTC нет: это небезопасно на этом железе.
- Отклонённые и непринятые эксперименты не публикуются как функции; если
  дельта имеет ценность, но не принята, она лежит в `experimental/` с явно
  указанным ограничением.
